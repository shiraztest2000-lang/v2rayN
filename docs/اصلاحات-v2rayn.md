# اصلاحات v2rayn

این سند، مجموعه تغییرات اختصاصی و تأییدشده فورک SHZ را ثبت می‌کند. مبنا، تغییراتی است که در ساخت نسخه
`7.25.6.012` با موفقیت در GitHub Actions اجرا و در Release نهایی تأیید شدند.

## تغییرات معتبر و حفظ‌شده

1. **پشتیبانی از `allowInsecure`**
   - تنظیم `allowInsecure` در کد برنامه حفظ می‌شود.
   - فایل اجرایی Xray رسمی با نسخه پچ‌شده SHZ جایگزین می‌شود.
   - بسته x64 از `Xray-windows-64.zip` و بسته x86 از `Xray-windows-32.zip` استفاده می‌کند.
   - آزمون واقعی parse/config گزینه `allowInsecure` روی Windows x64 در CI اجرا می‌شود و باید موفق باشد.

2. **ساخت مستقل Windows x64 و x86**
   - ساخت WPF ویندوز 64 بیتی از workflow اصلی build استفاده می‌کند.
   - ساخت WPF ویندوز 32 بیتی workflow مستقل دارد.
   - خروجی‌های Linux و macOS در Release این فورک منتشر نمی‌شوند.

3. **بسته‌بندی اختصاصی SHZv2rayN**
   - نام پوشه و ZIP با پیشوند `SHZv2rayN-` ساخته می‌شود.
   - پوشه `bin` مستقیماً داخل پوشه اصلی بسته قرار می‌گیرد.
   - ساختار ZIP قبل از انتشار اعتبارسنجی می‌شود.

4. **کنترل فایل‌های Release**
   - انتشار نهایی باید دقیقاً شامل دو فایل x64 و x86 باشد.
   - workflow بررسی نهایی، نام و مجموعه فایل‌ها را کنترل می‌کند.
   - شماره نسخه از قالب `major.minor.patch.NNN` پیروی می‌کند.

5. **منبع Xray**
   - Xray مورد استفاده بسته‌ها از فورک اختصاصی SHZ دریافت می‌شود:
     `https://github.com/shiraztest2000-lang/Xray-core`
   - این تغییر برای جلوگیری از بازگشت خطای حذف `allowInsecure` ضروری است.

## موارد نامعتبر یا موقت که در مجموعه نهایی نگه‌داری نمی‌شوند

- اجرای فایل اجرایی Windows یعنی `xray.exe` روی runner لینوکس؛ این روش با خطای `Exec format error` مواجه شد. آزمون به runner ویندوز منتقل شده است.
- تلاش‌های ناموفق قبلی برای پردازش heredoc و منطق اولیه تشخیص پیام commit؛ این موارد راه‌حل نهایی نیستند.
- منطق موقت `[replace-release]` برای حذف و بازسازی Release ناقص؛ پس از بازسازی موفق نسخه `7.25.6.012` دیگر بخشی از مسیر عادی انتشار نیست.
- هرگونه دریافت Xray رسمی به‌جای Xray پچ‌شده SHZ.

> تاریخچه commitهای قبلی برای ردیابی و ممیزی باقی می‌ماند؛ این سند فقط مجموعه نهایی و معتبر را تعریف می‌کند و تاریخچه Git را بازنویسی نمی‌کند.

## به‌روزرسانی خودکار از منبع اصلی

workflow زمان‌بندی‌شده هر هفت روز Release رسمی `2dust/v2rayN` را بررسی می‌کند.
اگر نسخه جدیدی وجود نداشته باشد، هیچ فایلی تغییر نمی‌کند و Release ساخته نمی‌شود.
اگر نسخه جدید باشد، تگ همان Release به شاخه `master` فورک merge می‌شود؛ سپس باقی‌ماندن اصلاحات اختصاصی بالا بررسی می‌شود.
در صورت conflict یا حذف‌شدن هرکدام از اصلاحات ضروری، workflow متوقف می‌شود و چیزی push یا منتشر نمی‌کند.

پس از merge موفق، شماره نسخه به شکل زیر تعیین می‌شود:
- بخش سه‌قسمتی نسخه از Release جدید upstream گرفته می‌شود.
- شمارنده سه‌رقمی انتهای آخرین Release فورک یک واحد افزایش می‌یابد.
- push تغییرات باعث اجرای workflow ساخت Release ویندوز x64 و x86 می‌شود.
